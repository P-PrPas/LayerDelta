# Synthetic datasets (v0.5-E2s)

Three seeded datasets for evaluator tests and the v0.5 benchmark. Every pixel is generated in this repository, so they need no licence (Q4 covers real datasets).
- **Generator:** `tools/bench/synthetic.py`. It is benchmark tooling, not product code: nothing in `src/` imports it.
- **Tests:** `tests/test_synthetic.py`.
- **Design:** [v0.5 design §2 and §5.3](../architecture/v0.5-evaluators-benchmark.md).

```
python tools/bench/synthetic.py shapes-seg --out DIR [--n 400] [--seed 0]
python tools/bench/synthetic.py boxes-det  --out DIR [--n 400]
python tools/bench/synthetic.py glyph-ocr  --out DIR [--n 600]
```

**Output.** Each command writes a directory in an [import format](datasets.md), which a person imports like any dataset with `POST /dataset-imports`. It also writes `synthetic.json` (generator, version, seed, n, format, task).

**Reproducibility.** The same generator version, seed and `n` give byte-identical files (a test checks this). The images are 8-bit PNG written by a stdlib encoder, so generating needs only numpy.

**Conditions.** Every dataset has two, so the splits are stratified by condition and a degraded-condition task (stratum S-nat) has both sides equally:
- `clean` and `noisy` for the shapes datasets: pixel noise SD 8 against 40;
- `clean` and `blur` for the glyphs.

Each image's condition is drawn with probability ½.

| Dataset | Format, task | Image | Content | Labels |
|---|---|---|---|---|
| `shapes-seg` | `image-mask`, segmentation | 32×32 RGB | 1 to 3 shapes (disc, square, upward triangle; radius 3 to 8), each a random colour with texture noise, on a random flat background with noise. Later shapes paint over earlier ones | a grayscale PNG mask of the paint: 0 background, 1 disc, 2 square, 3 triangle. `ignore_index` 255 is never in a mask; preprocessing pads with it |
| `boxes-det` | `image-boxes`, detection | 48×48 RGB | 0 to 4 shapes (radius 3 to 8) that never touch (a one-pixel gap). An image may have no shape, which exercises the F1 = 1.0 case | COCO boxes `[x, y, w, h]`: the tight extent of each shape's pixels. Categories 1 disc, 2 square, 3 triangle |
| `glyph-ocr` | `image-text`, OCR | height 20, width 2·2 + 12·L − 2 (L = 3 to 6 digits) | Digit strings drawn from a 5×7 glyph table defined in the generator, scaled ×2, 2 px apart, each glyph jittered vertically by up to 1 px. Dark ink (0 to 60) on light paper (190 to 255) with noise SD 6. `blur`: two passes of a 3×3 box blur | the digit string |

**Shape geometry.** A pixel belongs to a shape when its centre does:
- disc: within radius r;
- square: within half-side r;
- triangle: between the apex at `cy − r` and the base at `cy + r`, with half-width growing from 0 to r.

**What the tests check:**
- the files are byte-identical for a seed and differ for another;
- each dataset imports through the real import path, with both conditions on both splits;
- the PNG encoder round-trips through the worker's own decoder (`preprocess.decode`);
- masks hold exactly the four classes at the image size;
- boxes are inside the image, and the box rule is tight;
- every clean OCR line has one ink run per character (the glyphs are legible and separable);
- the ten glyphs are distinct.

**Version.** A change to any generated byte bumps `VERSION`. Benchmark tasks record the generator version and seed, and the dataset id hashes the content.

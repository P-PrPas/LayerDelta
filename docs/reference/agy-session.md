# The Antigravity session driver and its audit (v0.5-E7b, the part both isolation options need)

Code: `tools/bench/agy_session.py`. Tests: `tests/test_agy_session.py` (a fake `agy`, no host). Evidence for the host's behaviour: [the E7s spike](../research/v0.5-e7s-antigravity-spike.md). Design: [v0.5 §5.2](../architecture/v0.5-evaluators-benchmark.md).

`run_session(arm, session_dir, task, results=..., mcp=..., protected=[...], limits=Limits(...))` runs one benchmark session and returns its record (also `results/session.json`; the raw stream is `results/transcript.ndjson`). One session at a time.

- **Launch.** `agy -p <task> --model gemini-4-hydrogen-high --effort high --output-format stream-json --print-timeout <wall>s` in the session directory. `--dangerously-skip-permissions` is passed only with `skip_permissions=True`: that is the owner's decision and is off by default.
- **Budgets** (values pre-registered after the dry run), enforced from the stream while the session runs; the whole process tree is killed on a limit and the record says `stopped`:
  - `wall_seconds` (also given to the host as `--print-timeout`);
  - `steps`: the DONE tool steps of the stream;
  - `completion_tokens`: output plus thinking tokens of the agent responses.
  Total tokens (as the host counts them, prompt and cache reads included), input and cache-read tokens are reported, not limited.
- **The agent's store** (`~/.gemini/antigravity-cli`) is shared by every session of the OS account and holds what earlier sessions left. An inventory (file names, sizes and times, never contents) around a one-word session on this host showed it writing `conversations`, `brain` (knowledge; 4,500 files on the owner's account), `implicit`, `conversation_summaries.db`, `jetbox_summaries_proto.pb`, `log` and `cli.log`, `crashes`, `cache/conversation_metadata.json` and `cache/last_conversations.json` (titles of conversations), and also `presence` (lock files), `updater` and `last_check.timestamp` (no session content); `history.jsonl`, `annotations` and `scratch` are not written by a one-word session but hold earlier work. The driver moves `QUARANTINE` (all of the first group plus those three) to `bench-backup/` for the session, so the agent sees an empty store, keeps the session's own conversation in `results/conversations`, and puts everything back, also when the run fails. Auth and settings (`settings.json`, `installation_id`, the rest of `cache`) stay. A `bench-backup` left by a crash stops the next session (`StoreBusy`). **Anything else a session creates or changes raises `StoreChanged`** (with the record attached), so a host update that writes somewhere new is noticed rather than leaking. Because of that, `run_session` **refuses** (`NotBenchmarkAccount`) unless it is told this is the benchmark account: `benchmark_account=True`, `--benchmark-account`, or `AGY_BENCH_ACCOUNT=1` in that account's profile. It is never to be run on a person's own profile.
- **The environment.** The agent's process gets `scrubbed_env(env)`: the names it needs to start and find its configuration (`PATH`, `SYSTEMROOT`, `USERPROFILE`, `APPDATA`, `TEMP`, ...) and the host's own `AGY_*` settings; the driver's tickets, tokens and keys never reach the agent's shell. `env` is only what the caller adds (a proxy). The same environment is used for the `agy mcp` calls.
- **The bridge.** MCP configuration is global to the account, so arm L's session adds `layerdelta` (`agy mcp add layerdelta -- <command>`) before the run and removes it after; arm R refuses to start while `layerdelta` is configured (`McpConflict`), and so does arm L (someone else's session may be running).
- **The audit** reads every tool call of the transcript. A `violation` is what the pre-registered rule counts; a `review` is reported only.
  - `web_tool`: any web or browser tool (`search_web`, `read_url_content`, `browser_*`, ...).
  - `read_outside` / `write_outside` (review): a file tool whose path is outside the session directory and not protected (relative paths are resolved against it). The counted violations are the protected roots, so the list passed as `protected` must name everything the harness owns: the LayerDelta workspace, the MNIST archives, the holdout, the instance files (`tasks.json` holds the reference edits), the results directory (the other arm's transcripts) and the repository. The record also carries `response` (the agent's last message, for the `FINAL: <id>` line).
  - `protected_path`: a path under the agent's own store (`~/.gemini`), or under a root passed as `protected` (the LayerDelta workspace, the MNIST archives, the holdout), in a file tool, in a command, **or in the content of code the agent writes** (code written now and run later hides its paths from the command line; an absolute path elsewhere in written code is a review item).
  - `download` and `training`: the signatures of `mnist_bench.audit_text` (URLs, `curl`/`wget`/`Invoke-WebRequest`, `pip install`, dataset loaders; optimisers, `backward`, `fit`, ...) in a command or in code the agent wrote.
  - `path_outside` (review): an absolute path or `..` in a command that is not under the session directory and not protected (a program elsewhere, for example).
- **What it does not do.** Prevent. Everything is found after the fact. Prevention (a dedicated low-privilege OS account for the sessions and an outbound firewall rule) waits for the owner's decision (Q5) and is not here. The audit is needed under both options, and the audit must also be read for the real host once, because the tool and parameter names are those seen in the spike (`run_command` with `CommandLine`, `read_file` with `Path`); a tool the spike did not exercise (`view_file`, `write_to_file`, `grep_search`, ...) is matched by the parameter-name pattern (`path|file|dir|folder|target|cwd`) and should be checked in the dry run.

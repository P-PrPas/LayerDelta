# v0.3 — Graph semantics and coupling: technical design

Status: **proposed** (Senior AI Scientist) · Roadmap milestone v0.3 · Builds on [Architecture_Target §2–§3](Architecture_Target.md) and what v0.2 actually shipped: `tensors.py` (T1), `selector.py` + `inspect_ops.py` ([inspect-ops rev6](inspect-ops.md)), `edit.py` ([edit-program](edit-program.md)), `v2.py` (T4c). Open owner question: [QUESTION.md Q1](../QUESTION.md) (may LayerDelta run user model code?). This design isolates that decision behind one seam (§1), so most of v0.3 proceeds without it (§7).

## 0. Goal in one paragraph

v0.2 knows tensors but not what their axes mean: every axis is `unknown` and edits are tensor-local. v0.3 attaches a **graph** to a checkpoint and derives, by rule, (a) which tensors each graph node uses (**binding**), (b) what each tensor axis means (**roles**, with provenance), and (c) which slices of which tensors must move together (**coupling groups**), with explicit **opaque boundaries** where an op is not understood and a **coverage** number that says how much is understood. On top of that, selectors and edit programs gain `group` addressing and one function-preserving op, `permute_units`. Nothing in v0.2 changes meaning: with no graph attached, every response is byte-identical to rev6.

## 1. Graph sources: one provider seam

```
GraphProvider.build(spec) -> GraphIR (JSON)          # runs wherever the provider says (in-process or isolated worker)
bind(GraphIR, TensorTable) -> BoundGraph             # pure, generic, no provider code
derive(BoundGraph, RuleTable) -> roles, groups, opaque, coverage   # pure, generic
```

- **The trust decision lives in exactly one place: which providers are enabled and where they run.** Everything after `build` consumes a JSON IR (`ir_version`, canonical, hashed) and never imports user code, never unpickles, never needs torch modules.
- Providers (v0.3):

| Provider | Input | Runs code? | Where | Status |
|---|---|---|---|---|
| `builtin` | a module class shipped in our repo (the MNIST `ReferenceCNN`; test models under `tests/`) + example input shape | our code only | in-process | not blocked by Q1 |
| `torch_export` | user module factory (`package.module:callable`) + example input spec | **user code** | isolated worker process (same pattern as `job.py`), JSON-only result, timeout, no network assumption, human-only and opt-in per project | **blocked by Q1** |
| `onnx` | an `.onnx` file | no (protobuf parse) | in-process | not blocked by Q1; needs an `onnx` dependency decision |

- **Attachment key is the table signature, not the checkpoint id.** `table_signature = sha256(canonical [(name, dtype, shape) for every tensor, sorted])`. A graph built once applies to every checkpoint with the same signature: all children produced by `apply` (same header by construction), and fine-tuned siblings. The catalog stores `graphs(ir_sha256, provider, spec_sha256, table_signature, ir_json, created_at)`; `describe` looks the signature up.
- Graph spec for export providers: `{"entry": "pkg.mod:factory", "example_inputs": [{"shape": [1,3,224,224], "dtype": "F32"}], "root": "backbone" | null}`. `root` exports a submodule only (the workaround for detection post-processing / beam search, §8).
- Export settings (torch 2.6): `torch.export.export(model.eval(), example_args)` on CPU, default (training-IR) aten level. The IR is taken from `ep.graph` plus `ep.graph_signature.inputs_to_parameters` / `inputs_to_buffers`.

### Spike result (torch 2.6.0, the five T6 corpus families, CPU)

Run in the project venv from a scratch script (no repo change):

| Family | export | params bound | buffers bound | state tensors not in the signature | notable ops |
|---|---|---|---|---|---|
| ResNet-like | ok | 41 | 39 | none | `conv2d`, `batch_norm`, `add` (residual), `mean`, `linear` |
| U-Net-like | ok | 36 | 15 | none | `conv_transpose2d`, `cat`, `max_pool2d` |
| ViT-tiny | ok | 32 | 0 | `logit_scale`, `tok_embed.weight` (unused in forward) | `linear` (packed qkv), `reshape`, `permute`, `select`, `matmul`, `softmax`, `layer_norm` |
| CRNN-like | ok | 26 | 6 | none | **one** `aten.lstm.input` node with a flat param list, `getitem` |
| YOLO-like | ok | 31 | 24 | `anchors_unused` | `cat`, `upsample_nearest2d`, `silu` |

Findings that shape the design: (1) binding is exact and cheap through `graph_signature`; (2) **parameters unused by forward are absent from the signature**, so "unbound" is a real, common state and must be reported, not treated as an error; (3) `num_batches_tracked` placeholders exist but have **no users** in eval (bound, unused); (4) LSTM arrives as one fused node: its rule must decode the flat parameter list by position; (5) attention written by hand arrives as `linear → reshape → permute → select → matmul`, so qkv packing is only recoverable by tracking axis factorization through view ops (§4).

## 2. Torch-Pruning / DepGraph: reuse or write

Facts (from my knowledge as of this writing; **T1 verifies each line before the decision is final**): Torch-Pruning (`torch-pruning` on PyPI, VainF) implements DepGraph (Fang et al., CVPR 2023); MIT license; actively maintained 1.x series; supports Conv/ConvT/Linear/BN/LN/GN/Embedding/MultiheadAttention, concat/split/reshape/flatten, with an LSTM pruner of limited scope; it builds its dependency graph by running a forward pass on a **live `nn.Module`** and walking autograd `grad_fn` nodes, and it is designed to **mutate modules** (remove channels).

Decision proposed:

| Reuse | Write ourselves |
|---|---|
| As a **dev-only test oracle** (optional extra, never imported by `src/`): on the corpus, our coupling groups for conv/BN/linear/cat/add must match DepGraph's groups (acceptance A10) | The IR, binding and rule engine over the exported aten graph |
| Its documented op coverage as a checklist for our rule table | Provenance, opaque boundaries and coverage (DepGraph has no notion of "we do not understand this op") |

Why not a runtime dependency: (a) it needs the live module and autograd, so it would pull user-code execution into every consumer instead of keeping it in one provider; (b) its graph is keyed by module objects, not by stable tensor names on a content-addressed checkpoint; (c) its API is pruning (structural removal), while ours is element addressing with byte-exact children; (d) an unknown op there falls back to heuristics, while we need an explicit opaque boundary. A spike was not run (it needs a network install into a scratch venv); T1 runs it.

## 3. IR and derived structures

### 3.1 GraphIR (provider output, `ir_version: 1`, canonical JSON, `ir_sha256`)

```json
{"ir_version": 1,
 "provider": {"name": "torch_export", "version": "torch-2.6.0", "spec_sha256": "…"},
 "inputs":  [{"value": "v0", "shape": [1,3,32,32], "dtype": "F32"}],
 "params":  [{"name": "stem.conv.weight", "value": "p3", "kind": "parameter" | "buffer"}],
 "nodes":   [{"id": "n7", "op": "aten.conv2d.default",
              "args": ["v0", "p3", null, [2,2], [1,1], [1,1], 1],      // positional, values by id, literals inline
              "kwargs": {},
              "outputs": [{"value": "v8", "shape": [1,8,16,16], "dtype": "F32"}]}],
 "outputs": ["v40", "v41", "v42"]}
```

Only static shapes in v0.3 (the example input fixes them; spatial sizes never matter for coupling, channel sizes do).

### 3.2 Binding

`bind(ir, table)`: every IR param name must exist in the table with the same shape and a compatible dtype (the graph may be built in F32 and bound to a BF16 checkpoint: dtype is not part of semantics). Result per tensor: `bound` (list of `(node, arg position)`), `unused` (bound, no consumer, e.g. `num_batches_tracked`), or `unbound` (in the table, not in the graph, e.g. `tok_embed.weight`). IR params missing from the table, or shape mismatches, make the whole attach fail with `graph_mismatch` and the list of names. One param consumed by several nodes (tied weights such as embedding + LM head) is normal: its axes collect constraints from every use, and the graph **declares** the tie (`ties: [[names]]`), which closes the v0.2 gap where ties could only be guessed from identical bytes.

### 3.3 Axis spaces, roles, provenance

Each activation value dimension and each parameter axis is a node in a union-find over **unit spaces**. A role is assigned per `(tensor, axis)`:

| role | meaning |
|---|---|
| `out_unit` | indexes the units a node produces (conv/linear rows, ConvT axis 1) |
| `in_unit` | indexes the units a node consumes (conv/linear columns, ConvT axis 0) |
| `spatial` | kernel position (k_h, k_w, …) |
| `channel` | per-channel vectors (bias, norm weight/bias, running stats) |
| `packed(k)` + `factors` | axis is a concatenation of k equal parts, e.g. qkv `packed(3)·heads(2)·d_head(8)`, LSTM `gate(4)·hidden(24)` |
| `vocab`, `position` | embedding rows, positional tables |
| `counter` | 0-d integer buffers (`num_batches_tracked`) |
| `unknown` | nothing derived |

`provenance ∈ derived` (graph rule) `| declared` (profile override, v0.3 schema only) `| inferred` (unused in v0.3: no name heuristics, decision of PR #11) `| unknown`. Each role carries `basis` (the rule id and node, e.g. `rule:conv.weight@n7`).

### 3.4 Coupling groups

A group is a set of **members**, each a slice family of one tensor axis, indexed by a shared unit `u ∈ [0, size)`:

```
member = {tensor, axis, offset, block, period, repeat}
indices(u) = { offset + u*block + k*period + j  |  k < repeat, j < block }
```

This one formula covers identity (`block=1, repeat=1`), flatten-into-linear (`block=H·W`), cat offsets (`offset`), packed qkv (`repeat=3, period=E`) and LSTM gates (`repeat=4, period=H`). A group is **closed** when every value dimension in its union-find class is produced and consumed only by understood ops; otherwise it records `boundary: [{node, op, reason}]`. Permutation invariance is only claimed for closed groups.

**Graph outputs are boundaries** ([ADR 0001](adr/0001-depgraph-oracle.md)). A group whose union-find class contains a dimension of a graph output (for example `fc`/`head` out units) is `closed: false` with `boundary: [{node: "output", reason: "graph_output"}]`, and `permute_units` on it is refused with `group_not_closed`. Permuting such units is shape-valid but reorders the model's outputs, so it is not function-preserving.

Groups also carry `constraints`: `none`, or `within_blocks(n)` (GroupNorm with C/G per group: a permutation must keep units inside their norm group), or `heads(h)` (attention: units permute per head as a block).

### 3.5 Opaque boundaries and coverage

An op with no rule makes every dimension of its inputs and outputs a boundary: nothing couples across it, tensors it reads directly get `unknown` roles for the axes it would have explained, and it is listed in `opaque_ops` with its count. Coverage (extends rev6 `coverage`, still counted in **axes**):

```json
"coverage": {"unit": "axes", "derived": 912, "declared": 0, "inferred": 0, "unknown": 36,
             "opaque_ops": [{"op": "aten.cumsum.default", "count": 1}],
             "tensors": {"bound": 118, "unused": 26, "unbound": 3},
             "groups": {"closed": 41, "open": 2}}
```

## 4. Op rule table v1

Rules match aten ops of the torch 2.6 training IR. Notation: activation `x[N, C, …]`; "tie A ↔ B" unions two unit spaces with a member map.

| Op | Parameter roles | Coupling |
|---|---|---|
| `conv1d/2d/3d` (`weight[O, I/g, k…]`, `bias[O]`, `groups=g`) | w axis0 `out_unit`, axis1 `in_unit`, axes2+ `spatial`; bias axis0 `channel` | out dim1 ↔ w axis0 ↔ bias axis0. If `g == 1`: in dim1 ↔ w axis1. If depthwise (`g == I == O`, w axis1 = 1): in dim1 ↔ out dim1 (one space). Other `g > 1`: in dim1 ↔ w axis1 per group (member `offset = gi·I/g`), plus `within_blocks(O/g)` on the out space |
| `conv_transpose1d/2d/3d` (`weight[I, O/g, k…]`) | w **axis0 `in_unit`, axis1 `out_unit`** | in dim1 ↔ w axis0; out dim1 ↔ w axis1 (per group as above) ↔ bias axis0 |
| `linear` (`weight[O, I]`, `bias[O]`) | axis0 `out_unit`, axis1 `in_unit` | x last ↔ w axis1; out last ↔ w axis0 ↔ bias |
| `batch_norm` (`weight, bias, running_mean, running_var [C]`) | all axis0 `channel`; `num_batches_tracked` `counter` (unused) | in dim1 ↔ all four ↔ out dim1 (passthrough) |
| `layer_norm(x, normalized_shape, w, b)` | `channel` | last len(shape) dims of x ↔ w, b ↔ out (passthrough). Permutation-invariant; zeroing a unit is **not** removal (it still enters the mean/var), documented per group |
| `group_norm(x, G, w, b)` | `channel` | passthrough with `within_blocks(C/G)` |
| unary elementwise (`relu, gelu, silu, sigmoid, tanh, dropout`, scalar `mul/div/add`) | — | passthrough, all dims |
| `add/sub/mul` (tensor ⊕ tensor, broadcast) | — | dims aligned from the right are tied, size-1 broadcast dims are not. Residual add ties both branches' channel spaces |
| `cat(xs, dim)` | — | input i dim d ↔ out dim d with `offset = Σ sizes before i`; other dims tied |
| `split/chunk/slice/narrow/select` on a dim | — | inverse of cat (offset); `select` removes a factor |
| `flatten / reshape / view / unflatten` | — | **factor tracking**: a dim is a mixed-radix product of factors; merges and splits of contiguous dims that preserve factor order are tied with `block/period`; anything else (data-dependent, reordering inside a merge) → opaque |
| `permute / transpose` | — | moves dims, factors preserved |
| `mean/sum/amax/amin` over dims, `adaptive_avg_pool`, `max_pool`, `avg_pool`, `upsample_*`, `interpolate` | — | reduced or spatial dims dropped; channel dims passthrough |
| `matmul/bmm` (activation × activation) | — | contraction dims of both operands tied; batch and free dims passthrough. In attention this ties q and k per head on d_head, and v's d_head to the output |
| `scaled_dot_product_attention(q, k, v)` | — | q last ↔ k last; v last ↔ out last; head dim passthrough |
| `softmax/log_softmax(dim)` | — | passthrough (the softmax dim is a token dim, never a channel) |
| `embedding(weight[V, D], idx)` | axis0 `vocab`, axis1 `channel` | w axis1 ↔ out last. Vocab rows are addressed but never coupled |
| param added to activation (`x + pos_embed`) | `position` on token axis, `channel` on last | last dims tied by the add rule |
| `lstm(input, hx, params, has_biases, num_layers, dropout, train, bidirectional, batch_first)` | per layer l and direction d, params in order `w_ih[4H, I_l], w_hh[4H, H], b_ih[4H], b_hh[4H]`: axis0 `packed(4)·hidden(H)` (gates i, f, g, o), w_ih axis1 `in_unit`, w_hh axis1 `in_unit` (recurrent) | hidden unit u of (l, d) ↔ rows `{k·H + u}` of w_ih, w_hh, b_ih, b_hh (`repeat 4, period H`) ↔ w_hh column u (recurrent) ↔ output last dim at `offset d·H` ↔ layer l+1 w_ih columns at `offset d·H` (bidirectional cat). Layer 0 w_ih axis1 ↔ input last dim. `gru`: same with `repeat 3` |
| `getitem` on a tuple output | — | passthrough of that element |
| anything else | `unknown` | opaque boundary |

Attention written by hand (ViT corpus) becomes: `linear(qkv)` out dim = factors `(3, heads, d_head)` via `reshape`; `permute` moves factors; `select(·, k)` takes q/k/v; `matmul(q, kᵀ)` ties q and k on d_head per head; `matmul(attn, v)` passes v's d_head; `transpose + reshape` merges `(heads, d_head)` back into `proj` input. Result: three groups per block, **head** (`repeat 3` over qkv rows + proj columns, block d_head), **qk_dim** (q and k rows per head), **v_dim** (v rows ↔ proj columns per head), all closed.

## 5. Contract additions: inspect-ops rev7 sketch (additive)

Compatibility rule: **with no graph attached, every rev6 response is byte-identical.** New keys appear only when a graph is attached; old clients ignore them.

- `describe` result gains `graph: null | {"ir_sha256", "provider", "table_signature", "attached_at"}`; rows' `roles` become `[{axis, role, factors?, provenance, basis}]`; rows gain `binding: "bound" | "unused" | "unbound"` and `groups: [{group_id, axis}]`; `coverage` gains `tensors` and `groups` (§3.5).
- New routes (v2, `model:read`): `GET …/checkpoints/{id}/graph` (IR summary + paged nodes), `GET …/checkpoints/{id}/groups` (paged: `group_id, size, closed, boundary, constraints, members`). Human-only and capability-separate: `POST …/graphs` (attach: provider + spec, or ONNX upload) returning an import-style job; `torch_export` is disabled until Q1 and never callable by an agent token.
- **Group selector** (the key rejected as `unsupported_selector` in rev6): `{"group": "g_…", "units": [17] | {"start","stop"}}`. It expands deterministically to the tensor-local selectors of all members (§3.4) and keeps `resolved.selector` re-submittable: `resolved` echoes both the group form and the `expanded` tensor-local list. `selection_id` hashes `{group_id, ir_sha256, units}` so it stays a pure value. Accepted by `read_tensor`/`stats`/`diff` (returned per member) and by edit programs; `query` gains `where.group` to rank units of a group by a member statistic. Error `no_graph` (field `selector.group`) when none is attached.
- **Edit ops**: existing ops accept a group selector (applied to every member slice, then the T3 per-op rounding). New op `permute_units {"perm": [..]}` on a group selector covering the whole group: a pure gather on every member (bit-exact, no rounding). Refused with `group_not_closed`, `constraint_violation` (e.g. crossing GroupNorm blocks) or `invalid_permutation`. Recipes record the group expansion, not just the id, so verification and replay need no graph: `select` stays a canonical tensor-local selector per member and `group` becomes provenance metadata (`"via": {"group", "ir_sha256", "units"}`), outside the hashed `program` semantics. Planning reports `group` and `members`.
- **Engine**: `edit.ENGINE` gains ops revision 2. `verify_recipe` accepts a set of engines: revision 1 recipes stay valid (they can only use revision-1 ops); a revision 2 recipe may use `permute_units`. The rev6 strict equality check becomes membership in `SUPPORTED_ENGINES`.

## 8. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Export fails on data-dependent control flow (NMS, beam search, dynamic shapes) | no graph for detection/OCR heads | `root` submodule export; the rest stays tensor-level with `unknown` roles, honest coverage |
| Factor tracking through reshape/permute is the hardest rule and the most likely source of wrong groups | wrong coupling claimed as `derived` | A3 permutation tests on every closed group are the guard: a wrong group fails the forward-equivalence check; unknown patterns become opaque, never guessed |
| A graph built in one dtype/precision bound to another checkpoint | none for semantics | binding ignores dtype, checks names and shapes |
| User code execution (G6) | security | one provider, isolated worker, human-only opt-in, JSON-only result, blocked until Q1 |
| ONNX folding (BN into conv), renamed initializers | partial binding | report as unbound with reason; never claim roles for unbound tensors |
| aten op names drift across torch versions | rules stop matching | provider records torch version; rule table keyed by op overload name with a version guard; unknown → opaque, coverage drops visibly |
| Group zero is mistaken for unit removal (LayerNorm statistics, BN running stats) | misleading edits | per-group notes in `groups`, docs; `permute_units` is the only op claimed function-preserving |
| Recipe/engine compatibility | old recipes rejected | engine set, rev1 recipes verify unchanged (A9) |
| DepGraph facts in §2 are from memory | wrong reuse decision | G1 verifies before anything depends on it |
